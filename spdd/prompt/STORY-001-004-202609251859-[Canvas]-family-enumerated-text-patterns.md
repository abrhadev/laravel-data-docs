# Enumerated Values and Text Pattern Attributes

Family canvas for STORY-001-004 (`requirements/[User-story-4]enumerated-value-validation-attributes.md`). Owns `RegexProcessor`, `StartsWithProcessor`, `EndsWithProcessor`, `InProcessor`, `NotInProcessor`, `Processors/Base/ValueListProcessor`, and the registry rows `Regex`, `StartsWith`, `EndsWith`, `In`, `NotIn`, `Alpha`, `AlphaDash`, `AlphaNumeric`, `Lowercase`, `Uppercase`.

**Story partly shipped.** `In` and `NotIn` (AC1, AC4, AC7, AC8, AC9, AC10) are specified here; STORY-001-004 still extends this canvas with `/spdd-prompt-update` for `Enum`, `NotRegex`, `DoesntStartWith` and `DoesntEndWith`.

Related canvases: attribute processing framework (`StaticAttributeProcessor`, registry); pipeline canvases (`ExampleGenerationStage` draws string examples from the pattern rules, and keeps a `format` example only when the field's rules accept it).

Carved out of the former attribute processors canvas; git history keeps it.

## Requirements

- Publish the values an `#[In]` accepts as an OpenAPI allowed-value set (`enum`), typed to the field, and as a sentence; on a PHP-enum property, publish one set, the enum's cases the `#[In]` allows.
- State the values an `#[NotIn]` rejects, without publishing an allowed set (AC4); with an `#[In]` on the same field, publish the allowed set without the rejected values (AC7), in either declaration order.
- Publish a string field's required shape as an OpenAPI `pattern` plus a sentence: a declared regex, a required prefix or suffix, or a fixed character class.
- Publish only a pattern an OpenAPI consumer reads the way Laravel does. OpenAPI's `pattern` is an ECMA-262 regex with no delimiters and no flags; a declared PHP regex is translated to it, and one that cannot be translated exactly publishes no pattern, only its sentence.

## Entities

`RegexProcessor`, `StartsWithProcessor` and `EndsWithProcessor` implement `AttributeProcessor` directly. `InProcessor` and `NotInProcessor` extend the family-private `Processors/Base/ValueListProcessor`, which reads an `In` or `NotIn`'s values by reflection (through a wrapped Illuminate rule's `values` when there is one), flattens and string-forms them as Laravel compares them, filters them by the field's numeric type, and narrows an `EnumInfo` to a set of case string forms. The five character-class rows are `StaticAttributeProcessor` instances.

## Approach

**`NotIn` is the negation of `In`, and reconciles with it.** Verified on 2026-09-26: Laravel's `validateNotIn` is `! validateIn`, so `#[NotIn(['admin', 'root'])]` rejects exactly the string forms `admin` and `root` (`Admin` passes; `2` and `"2"` both fail `not_in:1,2`). On an array field `validateIn` needs every item in the set, so `not_in` fails only an array whose items are all forbidden: `['admin']` fails `#[NotIn(['admin'])]`, `['admin', 'bob']` and `['bob']` pass. `#[In(['pending', 'shipped', 'cancelled'])]` with `#[NotIn(['cancelled'])]` rejects `cancelled` in either order, and an enum-typed property with `#[NotIn(['admin'])]` rejects the `admin` case. `#[Rule('not_in:a,b')]` behaves as `#[NotIn(['a', 'b'])]`. So on a field that is not an array, the published allowed set is the declared `In` set minus the `NotIn` values, and a PHP-enum property drops the rejected cases; with no `In`, the rejected values are stated. `In` and `NotIn` record their sets on the context in either order and write no sentence; `TypeDescriptionStage` (parameter metadata pipeline canvas) writes the sentences once both are known.

**`In` is published as the set Laravel compares against.** Verified on 2026-09-26 against real Data classes' `getValidationRules` and Laravel's validator: `#[In(['pending', 'shipped'])]` becomes `in:"pending","shipped"`, and a value passes only when its string form is exactly one of them (`PENDING` fails, `"1.50"` fails `in:1.5`, `2` and `"2"` pass `in:1,2`). A backed enum case counts by its value, a pure one by its name; a comma inside a value is kept. On an array field every element must be in the set. `#[In([])]` becomes `in:` and rejects every value. `#[Rule('in:a,b')]` behaves as `#[In(['a', 'b'])]` and reaches `InProcessor` through the framework's rule-string expansion. A property typed as a PHP enum only ever holds one of its cases (Laravel Data adds an `Enum` rule for a backed enum; a pure enum gets no rule, but only a case can be cast into the property), so both apply and the published set is their intersection. `In` exposes its values only through `getRule(ValidationPath)`, and `tests/ArchTest.php` confines `ValidationPath` to `RequirementResolver`, so `ValueListProcessor::declaredValues` reads the attribute's private `values` by reflection (for `NotIn` as for `In`), and an `Illuminate\Validation\Rules\In` inside them (`In::create`, a rule string) through that rule's `values`, as the `Password` processor reads its attribute. An `ExternalReference` among the values documents nothing, as for `StartsWith`.

**An argument that cannot be documented is skipped.** Spatie types the arguments of `Regex`, `StartsWith` and `EndsWith` as `…|ExternalReference`, and accepts a `StartsWith`/`EndsWith` with no values, which Laravel then fails for every value (see the Operations note). Each processor tests the argument's type before using it and returns without writing anything when it is not a string it can render. An `ExternalReference` is never dereferenced.

Known divergences:

- `In::getRule()` and `NotIn::getRule()` replace an `ExternalReference` in their values with the resolved value. Requirement resolution does not call them; Spatie's `RuleDenormalizer` does, when the application validates the class, calls `getValidationRules`, or casts the attribute to a string. So once that has happened in the same process, a referenced `#[In]` or `#[NotIn]` value can be published resolved rather than skipped. Documenting a class twice is harmless.
- On an array field an `#[NotIn]` is published as a sentence only, never subtracted from an `#[In]`'s item set: `not_in` there only rejects an array whose items are all forbidden, so an allowed array may still contain a forbidden item.
- The rejected values of an `#[NotIn]` alone are not published as structured data (no OpenAPI `not`), only stated.
- A PHP-enum property's cases are narrowed by `In` and `NotIn` (through `ParameterContext::keepEnumCases`, which `ValueListProcessor::narrowEnum` calls) and by `Accepted` / `Declined` (cross-field acceptance canvas), never by `valuePatterns`: `#[StartsWith('d')] Status` still publishes every case, including those the pattern rule rejects. An exact pattern (`StartsWith`, `EndsWith`, `Regex`) is always published beside them (parameter metadata canvas), so a validating client still rejects those cases. A character-class pattern, which only approximates Laravel's rule, is left out when a case Laravel's rule accepts fails it, judged over all the cases, so the result is the same in every build (`#[Lowercase]` beside `in_progress` publishes none). The example is still drawn from every case, so it may be one the pattern rule rejects.
- A declared value that no value of the field's type can have (`#[In(['abc'])]` on an integer field) is left out of the set; when none is left, the empty-set note (Operations, `In` row) is published.
- A `Regex` or `StartsWith`/`EndsWith` attribute whose argument is an `ExternalReference` produces no description and no pattern. For `StartsWith`/`EndsWith`, one reference among several values drops them all.
- `StartsWith`/`EndsWith` overwrite `pattern` entirely; they do not AND with an existing pattern. So does a translated `Regex`, and so do the static rows. A `Regex` that cannot be translated leaves an earlier pattern in place: it still holds, as a necessary condition, so `#[Alpha, Regex('/x/i')]` publishes Alpha's `^[a-zA-Z]+$`.
- A PCRE `$` without the `D` modifier also matches before a final newline, so Laravel accepts `"abc\n"` for `/^[a-z]+$/`; the published `^[a-z]+$` does not. The pattern is kept as written: the exact spelling, `(?=\n?$)`, is unreadable and defeats Faker's `regexify`.
- Without the `u` modifier PHP matches bytes, so `/^.$/` rejects `é` (two bytes) while ECMA-262 accepts it. PCRE's `.` excludes only `\n` and its `\s` is ASCII, where ECMA-262's `.` also excludes `\r`, ` ` and ` ` and its `\s` includes Unicode spaces. These differ only for non-ASCII or control characters and are not translated. The `#[In]` filter does not share this gap: `RegexProcessor` also appends the declared regex to `valueRegexes`, which is matched as Laravel runs it, so `#[In(['café', 'tea']), Regex('/^\w+$/')]` publishes only `tea` and the `u` form keeps both (`InTest`).
- A `Regex` that publishes no pattern (a flag such as `i`, or a PCRE-only construct) still gets an example the regex accepts, with or without a format beside it: the example generation canvas draws from the regex body with its own PCRE reader (open-ended counts such as `{4,}`, nested groups, `\xHH`, Unicode and negated classes drawn from the characters they match; lookarounds and inline flags draw nothing), and keeps a draw only when the declared regex matches it; a construct the reader cannot read (`\k`, a conditional), or rules no value meets, may leave no draw that passes, and then the example is a basic string or a draw that the published pattern, if any, matches.
- `StartsWith`/`EndsWith` escape with `preg_quote`, which also escapes `#`, `-`, `:`, `=`, `!`, `<`, `>` and `}`. ECMA-262 in Unicode mode rejects those identity escapes outside a class, so `#[StartsWith('a-b')]` publishes `^(a\-b)`, which a validator compiling patterns with the `u` flag rejects as invalid.
- The character-class patterns are ASCII-only and stricter than Laravel: `alpha`, `alpha_dash` and `alpha_num` accept Unicode letters and marks, and `lowercase` / `uppercase` accept any string without an upper-case (respectively lower-case) character. The published pattern keeps that divergence, but each row also gives Laravel's rule for letters as its value pattern, appended to `valuePatterns` (`[\pL\pM]`, `[\pL\pM\pN_-]`, `[\pL\pM\pN]`, and no upper- or title-case letter for `lowercase`, no lower- or title-case letter for `uppercase`), so an `#[In]` value only the ASCII approximation rejects (`in_progress`, `en-us`, `café`) is still published; `InTest` pins these against Laravel's validator. The published set then leaves out the pattern that rejects one of its values (parameter metadata canvas, `publishedPattern`), so the schema stays satisfiable; the same holds for an enum case Laravel's rule accepts and for a generated example Laravel's rules accept, while an explicit `#[Example]` Laravel rejects leaves the pattern in place. A `Regex` on the field does not keep a character-class pattern written after it: only the regex's own translation counts as exact (`regexPatterns`), so `#[Regex('/^\d{3}$/'), Lowercase]` publishes no `^[a-z]+$` beside the example `333`. `lowercase` / `uppercase` compare the value with its lower- / upper-cased form, which the category patterns approximate: a letter with a case mapping but no `Lu`/`Ll`/`Lt` category (`Ⅻ`, `ĸ`) is judged differently.
- Format rules that need the network (`ActiveUrl`, an `Email` whose only mode is `dns`, and `Password`'s `uncompromised`) do not narrow an `#[In]` set: a value only such a rule rejects is still published, stated and drawn (parameter metadata canvas). The other format rules (`Email`, `Url`, `Uuid`, `IP`, `IPv4`, `IPv6`, `Json`, `Date`, `DateFormat`, `Password`'s length and character classes) narrow it through `valueRules`; attributes the package does not register (`Timezone`, `MacAddress`, `NotRegex`, …) narrow nothing.
- Values interpolated into sentences are not escaped; `preg_quote` is applied only to the `pattern`.
- `Regex`, `StartsWith` and `EndsWith` call `parameters()` directly rather than through `ConditionProcessor::parametersOf`; none of their attributes has the uninitialised-property defect. `In` and `NotIn` do not call it at all.
- Rule strings for this family (`#[Rule('regex:/…/')]`, `starts_with:`, `ends_with:`, `in:`, `not_in:`, `alpha`, …) are documented like the attributes, through the expanded rules, and a declared attribute that a later same-class `#[Rule]` replaces is not documented (framework canvas).

**A declared regex is published as ECMA-262, or not at all.** `RegexProcessor` keeps the sentence exactly as declared and derives the `pattern` in four steps. Any step that fails publishes no pattern (an earlier pattern on the field stays); the sentence stays. A wrong pattern is worse than none: a validating client or mock server would reject values Laravel accepts.

1. **Compiles.** A regex PHP cannot compile (`@preg_match($regex, '') === false`) has nothing to translate.
2. **Delimiters.** Leading whitespace is skipped, as PHP does. The first character opens; `(`, `[`, `{` and `<` close with `)`, `]`, `}` and `>`, any other with itself. The closing delimiter is its last occurrence: in a regex that compiles, only modifiers and whitespace follow it.
3. **Modifiers.** Whitespace among them is ignored, as PHP does.
   - Kept, because they do not change which values match, or align PCRE with JSON Schema: `D` (makes `$` ECMA-262's), `S` and `X` (no effect in PCRE2), `U` (swaps greediness, which never changes whether a value matches), `r` (acts only with `i`), `u` (PHP then matches code points, which is how JSON Schema evaluates a pattern), except that under `u` PCRE also reads `\d`, `\w` and `\b` as Unicode classes, which ECMA-262 keeps ASCII even in its own `u` mode, so a `u` regex using `\d \D \w \W \b \B` publishes no pattern (`/^\w+$/u` would publish a pattern rejecting `café`, which Laravel accepts).
   - `A` (anchored) publishes `^(?:body)`.
   - `n` (no auto-capture) is kept; a backreference publishes no pattern anyway (below).
   - `i`, `m`, `s`, `x`, `J` and any other: no pattern. OpenAPI's `pattern` carries no flags, and emulating one means rewriting the body. `J` exists to allow duplicate group names, which ECMA-262 accepts only in separate alternatives.
4. **Body.** One scan, tracking whether it is inside a character class. A construct both dialects read the same way is copied; a few are respelled; anything else publishes no pattern.
   - Copied: `\d \D \w \W \s \S \b \B \f \n \r \t` (the first six only without `u`, above); `\0` not followed by a digit; `\xHH`; `\cX` with a letter; `\p{…}` / `\P{…}` naming a General_Category (`L`, `Lu`, `Nd`, …); groups `(`, `(?:`, `(?=`, `(?!`, `(?<=`, `(?<!`, `(?<name>`; quantifiers `*`, `+`, `?`, `{n}`, `{n,}`, `{n,m}` and their lazy `?` forms; an escaped ECMA-262 syntax character (`^ $ \ . * + ? ( ) [ ] { } |`) or `/`, and `\-` inside a class.
   - Respelled: any other escaped non-alphanumeric loses its backslash (`#a\#b#` publishes `a#b`); a `]` first in a class, which PCRE reads as a literal, becomes `\]`; a `[` inside a class becomes `\[`; a `{` that does not start a quantifier, a lone `}` and a lone `]` are escaped. ECMA-262 in Unicode mode rejects each of these as PCRE spells it.
   - No pattern: every other alphanumeric escape (`\A \z \Z \G \h \H \v \R \N \K \X \Q \E \e \a \g \o`, `\x{…}`, `\pL`, a script such as `\p{Greek}`, octal `\0nn`, a digit escape inside a class); any other `(?` group (inline flags, atomic, comment, branch reset, recursion, `(?P<`, `(?'`); a `(*` verb; a possessive quantifier (`a*+`); `{,n}` or a quantifier with spaces, which PCRE2 10.43+ reads as a quantifier and ECMA-262 does not; a POSIX class (`[[:alpha:]]`); any backreference (`\1`–`\9…` or `\k<name>`), because ECMA-262 lets a reference to a group that did not take part match the empty string where PCRE fails it, so `/^(?:(a)|b)\1$/` would accept `b`; a quantifier directly after a lookaround (`(?=a)?`, `(?<=a)*`), which PCRE accepts and ECMA-262 rejects.

`#[Regex('/^[a-z]+$/')]` therefore publishes `^[a-z]+$`, `#[Regex('#^a/b$#')]` publishes `^a/b$`, `#[Regex('{^a{2}$}')]` publishes `^a{2}$`, and `#[Regex('/^[a-z]+$/i')]` and `#[Regex('/^\w+$/u')]` publish no pattern, while `#[Regex('/^\p{Lu}[0-9]{2}$/u')]` publishes `^\p{Lu}[0-9]{2}$`.

## Structure

`Processors/RegexProcessor.php`, `StartsWithProcessor.php` and `EndsWithProcessor.php` implement `AttributeProcessor` directly; `Processors/InProcessor.php` and `NotInProcessor.php` extend the family-private `Processors/Base/ValueListProcessor.php`. The static rows live in `AttributeProcessorRegistry::registerDefaults()`.

## Operations

The example rule, a pattern example (`generatePatternExample`: a draw of the pattern or of another pattern rule of the field by the stage's own PCRE reader, or two such draws joined or laid over each other, fitted to the length bounds and kept only when it is not empty and every pattern rule accepts it, preferring one the published pattern also matches; when rules no value meets leave none, a basic string or a draw the published pattern matches; example generation canvas), applies only to a property typed exactly `string`, with no explicit example, no enum, no `#[In]` set (the example is drawn from the set's values the pattern accepts) and no numeric-string comparison; `string[]` items get a word. When a `format`, an example-only `exampleFormat` (`IP`, `Date`) or a `dateFormat` is also set, example generation (example generation canvas) keeps a format example only if it matches the pattern (or the pattern only approximates Laravel's rule, as a character class does, when Laravel's own rule decides) and every other rule of the field, lays the pattern rules' own examples (never the approximate pattern's) over a format example when no draw does, up to a separator as well, so a domain suffix replaces the drawn domain, and otherwise gives the pattern example. A regex that publishes no pattern takes the same route beside a format. So `#[Email, StartsWith('a')]` gets an email that starts with `a`, `#[Email, EndsWith('@corp.com')]` an address at `corp.com`, `#[Url, EndsWith('.pdf')]` a URL ending in `.pdf` (with `Lowercase` too, publishing no `^[a-z]+$`), `#[IP, StartsWith('10.')]` an address in `10.`, `#[StartsWith('img_'), EndsWith('.png')]` `img_.png`, `#[Email, Lowercase]` a lower-case email (and no published `^[a-z]+$`, which the email fails), `#[Json, StartsWith('[')]` a JSON array, and `#[Email, Alpha]`, which no value meets, gets a pattern example.

## Norms

- Values in sentences are wrapped in `<code>`; no field names appear in this family today.

## Safeguards

- An `#[NotIn]` alone publishes no allowed set, and with an `#[In]` on a non-array field the published set never holds a rejected value, in either declaration order. `NotInTest` checks each case against Laravel's validator (every published value passes; every stated rejected value fails, and on an array only when all items are forbidden) and validates the examples over repeated runs.
- An `#[In]` publishes only values Laravel accepts, every pattern rule of the field included (a value `Uppercase` rejects is left out by the pipeline's `acceptedAllowedValues`, and with two pattern rules a value either rejects, and a value a declared `Regex` rejects as Laravel runs it) along with the field's length, numeric and divisor bounds and its offline format rules (`InTest` rows `in_email`, `in_ip`, `in_uuid`, `in_json`, `in_url`, `in_date`, `in_date_format`, `in_password`; network rules excepted, Known divergences), and the published `enum` never holds a value outside the declared set. `InTest` checks each published set against Laravel's validator (every published value passes, and a value outside it fails) for string, integer, float, array, enum-typed, enum-valued, empty and rule-string declarations, and for numeric values not written as their number prints (`'01'` on an integer, `'1.50'` on a float), and validates each example against the Data class's own rules over repeated runs.
- `In` and `NotIn` write only `allowedValues`, `excludedValues` and, on a PHP-enum field, a narrowed or cleared `enumInfo` (with `allowedValues = []` when cleared); never a sentence, bound, format or pattern. `InProcessorTest` and `NotInProcessorTest` pin it.
- `StartsWith`/`EndsWith` never publish a match-everything pattern (`^()`, `^(a|)`): an empty needle is skipped as Laravel skips it, and with no needle left the field gets the fails-validation note, which Laravel confirms. A comma inside a value splits it into two needles, as at runtime. `EnumeratedTextPatternsTest` checks both against Laravel's validator; the two processor Pest files pin the split, the skipped empty value and the note.
- Each processor's Pest file has a case for an `ExternalReference` argument, and `StartsWith`/`EndsWith` for a bare declaration.
- A published `Regex` pattern accepts what Laravel accepts on the tested values. `tests/Integration/Pipeline/EnumeratedTextPatternsTest.php` runs declared regexes (each delimiter kind, the kept modifiers, `A`, the respelled escapes) through the default pipeline, pins the published pattern, and checks it, compiled with `u`, against Laravel's validator and the fixture Data class's own rules on matching and non-matching values. It also pins that each rejected modifier and PCRE-only construct publishes no pattern and keeps the sentence, including `\w` and `\d` under `u` (`unicode word class`, `unicode digit class`); its `unicode modifier` row publishes `^\p{Lu}[0-9]{2}$`. The check runs PCRE with `u`, not an ECMA-262 engine, so it cannot detect a construct the two dialects read differently on values it does not try; the `u` escape rule above is pinned by rows, not by that check.
- A generated example meets both a format and a pattern where some value can: the same test validates repeated examples of `#[Email, StartsWith('a')]`, `#[Email, EndsWith('.com')]`, `#[Uuid, StartsWith('a')]`, `#[Url, EndsWith('.pdf')]`, `#[Url, EndsWith('.com')]`, `#[IP, StartsWith('10.')]`, `#[Email, StartsWith('a'), EndsWith('.com')]` and `#[Uuid, StartsWith('a'), EndsWith('f')]` against the Data class's rules, and pins that the example of `#[Email, Alpha]` matches the pattern.
